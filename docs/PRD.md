# PRD：世界杯球迷社区（MBTI Cosmos 重构）

## 1. 产品目标

将世界杯预测网站从"孤岛式预测工具"升级为"球迷社区"，让球迷可以自由发帖讨论、查看实时赛况、将预测结果以图片卡片形式分享传播，形成"预测→讨论→分享→拉新"的闭环。

## 2. 目标用户画像

| 画像 | 特征 | 核心诉求 |
|------|------|----------|
| **硬核球迷** | 25-40 岁，常年关注足球，有自己主队 | 实时赛况、深度讨论、赛后复盘 |
| **赌球替代型球迷** | 20-35 岁，喜欢竞猜但不愿涉赌 | 预测胜率、和朋友比拼、分享战绩 |
| **社交型球迷** | 18-30 岁，世界杯期间跟风看球 | 发帖互动、表情包、轻松氛围 |
| **路人间歇型** | 偶尔看世界杯，无固定主队 | 快速了解赛况、扫别人分享的图片进来看热闹 |

## 3. 用户故事（按优先级排列）

### P0 — 必做

1. **As a** 球迷，**I want** 用手机号+昵称一键登录，**so that** 我能拥有身份参与社区讨论，而不需要记密码。
2. **As a** 球迷，**I want** 在社区里发帖和回帖，**so that** 我能和其他球迷交流观点，而不是对着一个只有自己能看到的假评论区。
3. **As a** 球迷，**I want** 看到实时赛况（比分、赛程、积分榜），**so that** 我不用切换到其他 App 就能掌握最新动态。
4. **As a** 球迷，**I want** 把预测结果生成带二维码的图片卡片，**so that** 我能分享到微信群/朋友圈，别人扫码就能进网站。

### P1 — 应做

5. **As a** 球迷，**I want** 按球队/比赛筛选帖子，**so that** 我能快速找到自己关心的话题。
6. **As a** 球迷，**I want** 给帖子点赞，**so that** 我能表达认同而不必打字。
7. **As a** 球迷，**I want** 实时赛况有推送通知（进球/红牌等关键事件），**so that** 我不会错过重要时刻。

### P2 — 可做

8. **As a** 球迷，**I want** 关注其他用户，**so that** 我能跟踪有趣球迷的动态。
9. **As a** 球迷，**I want** 累计预测准确率排行榜，**so that** 我有持续回来预测的动力。
10. **As a** 球迷，**I want** 暗色/亮色主题切换，**so that** 夜间浏览更舒适。

## 4. 功能需求池

### P0 — 必做（MVP）

| 编号 | 功能 | 说明 | 验收标准 |
|------|------|------|----------|
| F01 | 手机号+昵称登录 | 无需验证码，输入手机号和昵称即可注册/登录；手机号为唯一标识，昵称可重复 | 登录成功后 localStorage 存 token，页面刷新不丢失身份 |
| F02 | 社区发帖 | 用户可发布帖子（标题+正文+可选关联球队/比赛标签），帖子对所有用户可见 | 帖子写入 Supabase，其他用户可实时看到新帖 |
| F03 | 社区回帖 | 用户可在任何帖子下回复，回复即时可见 | 回复写入 Supabase，按时间正序展示 |
| F04 | 实时赛况修复 | 补全 football-data.org API token，修复赛程/比分/积分榜数据展示 | 页面能展示真实比赛数据，"最后更新"时间 ≤ 5 分钟前 |
| F05 | 预测图片卡片 | 预测结果渲染为图片（含双方队名、国旗、胜率、二维码），可长按保存或分享 | 生成的图片清晰可读，二维码扫码跳转网站首页 |

### P1 — 应做

| 编号 | 功能 | 说明 |
|------|------|------|
| F06 | 帖子筛选 | 按球队标签、比赛标签筛选帖子列表 |
| F07 | 点赞 | 对帖子/回复点赞，显示点赞数 |
| F08 | 关键事件推送 | 进球/红牌等关键事件浏览器通知（需用户授权） |

### P2 — 可做

| 编号 | 功能 | 说明 |
|------|------|------|
| F09 | 用户关注 | 关注其他用户，查看关注列表 |
| F10 | 预测排行榜 | 累计预测准确率排名 |
| F11 | 主题切换 | 暗色/亮色模式 |

## 5. UI 关键页面列表

| 页面 | 路由 | 核心元素 |
|------|------|----------|
| **首页（Hero + 预测器）** | `/` 或 `#predictor` | 保留现有 Hero 区 + 预测器，新增"分享为图片"按钮 |
| **实时赛况** | `#live` | 修复后的赛程/比分/积分榜，数据来源标注 |
| **社区首页** | `#community`（新增） | 帖子列表（按时间/热度排序）、发帖按钮、筛选栏（按球队/比赛） |
| **帖子详情** | `#post/:id`（新增） | 帖子正文 + 回复列表 + 回复输入框 |
| **球队百科** | `#teams` | 保留现有 |
| **夺冠热榜** | `#ranking` | 保留现有 |
| **登录弹窗** | 模态框 | 手机号输入 + 昵称输入 + 登录按钮（复用现有弹窗，调整逻辑） |
| **分享图片弹窗** | 模态框 | 预测结果图片预览 + "保存图片"按钮 + "分享到微信"引导 |

### 关键交互流程

**发帖流程**：社区页点击"发帖"→ 弹出发帖编辑框 → 填写标题/正文/可选标签 → 提交 → 帖子出现在列表顶部

**分享流程**：预测器得出结果 → 点击"分享为图片" → 生成含二维码的图片卡片 → 弹窗预览 → 保存/分享

## 6. 待确认问题

| # | 问题 | 影响范围 | 建议 |
|---|------|----------|------|
| Q1 | football-data.org 免费 API 的调用频率限制是多少？是否够用？ | F04 实时赛况 | 免费版 10 次/分钟，建议前端 5 分钟轮询一次并做本地缓存 |
| Q2 | 社区内容是否需要审核/过滤机制？ | F02/F03 发帖回帖 | MVP 阶段暂不做，后续加举报功能；Supabase 可快速删除违规内容 |
| Q3 | 图片卡片中的二维码指向哪个 URL？ | F05 分享图片 | 建议指向首页 `https://jyuxin1997-arch.github.io/mbti-cosmos/`，后续可加 UTM 参数追踪来源 |
| Q4 | Supabase 免费版 500MB 存储是否足够？帖子是否只存文本？ | 全局架构 | 纯文本帖子约 1KB/条，500MB ≈ 50 万条帖子，MVP 阶段足够；图片走外部链接或 base64 内嵌 |
| Q5 | 手机号不做验证，是否担心恶意注册/刷帖？ | F01 登录 | MVP 阶段接受此风险；后续可加频率限制（同 IP 每小时最多 N 条） |
| Q6 | 现有 localStorage 评论数据是否需要迁移？ | F02/F03 | 不迁移，上线时清零重开，旧评论本就只有自己可见 |

## 技术约束摘要

| 约束 | 方案 |
|------|------|
| 后端 | Supabase（免费版：500MB PostgreSQL + Auth + Realtime） |
| 前端 | 仍部署在 GitHub Pages（纯静态） |
| API | football-data.org 免费版 |
| 登录 | 手机号 + 昵称，无验证码 |
| 图片生成 | 前端 Canvas 渲染 → 导出 PNG |
| 二维码 | 前端 JS 库生成（如 qrcode.js） |
| 费用 | 全部免费方案 |
